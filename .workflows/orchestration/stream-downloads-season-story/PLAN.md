## Scope

**In scope:** a persisted download queue for the Stream side (torrent first, cloud as fallback or by choice), the owner mark that exempts a torrent from the prune, season downloads from a pack, the `/api/stream/downloads` routes and the `direct_stream_cache` tool's torrent option, download buttons and progress bars on the title page, the Cache page's Downloading filter, progress bars and reason labels, a web-written season story and episode story with sources, their modal, the guides, pictures and feature map.

**Out of scope:**
- The library (DM/DS, `movie_files`, VLC): a download is never moved into the library roots.
- New watch codenames: none is added.
- The chat bar: it still does not cache or download (a Claude Code request, as today).
- Raising `NOTESD_TORRENT_BUDGET_GB`: see Decisions.
- Film stories: the film's book icon keeps its present route unless phase 6 gets it for free through the shared writer (the web-first order applies to it too; no season button exists for a film).
- Uploading/seeding policy, new torrent indexes, new cloud providers.

## Invariants

1. The tree typechecks (`npm run typecheck`) and `npm test` passes at the end of every phase, `tests/unit/docs/reference.test.ts` included: a phase that adds a route, tool parameter or env var regenerates the references in the same phase.
2. Single writers: `TorrentsRepo` alone writes `stream_torrents`; `DirectStreamRepo` alone writes `stream_caches`; `MoviesRepo` alone writes every `movie_*` table; the new `stream_downloads` table has exactly one writer, a new `DownloadsRepo`.
3. Nothing starts unasked: a download starts only from the owner's click or tool call, for exactly the title, season or episode named. Fetch-ahead and pause caching keep their present behaviour.
4. A torrent is in the swarm only while something uses it: a download job holds it and lets it go when its files are whole or the job fails or is cancelled. Only video and subtitle files are selected. Nothing from a torrent is run.
5. Original language only: a download applies the same audio check a play does (`MovieStreams.originalLanguage`), before the bulk of the file is fetched.
6. A download switches WARP only on SSID `Employee`, only after a torrent step found no peer at all with WARP off, only through the stream service's one `WarpHolds` (the engine never holds `set`), and puts it back as R1.12 says. A WARP the owner turned on is never touched; `claude/streaming/warp.mjs` stays the one place `warp-cli` and `netsh` run. (Until phase 10 lands, phase 2's interim rule holds: no download switches WARP.)
7. `titleSearchExclusion` and the `/sync-subtitle` rounds are not loosened; the seek-preview rules hold (no network, no swarm, one niced ffmpeg).
8. Rows record their host; a download row of another machine reads `available: false`.
9. Every path, binary, fetch, clock, SSID reader, engine and model writer is injected; no test touches the network, the real `~/.claude` or the streaming Chrome. Nothing new runs with `DEFAULT_MOVIES_CONFIG` or when `NOTESD_TORRENT=off` and the cache is off.
10. No list stores watch state; ids are never invented in application code.
11. Web UI: icon-only buttons with Phosphor icons, `data-tip` and `aria-label`, in the page's existing classes (`ibtn`, `pbtn`); never a text button.
12. The story writer never invents: a model answer with no source for an episode is stored as "no source found" for that episode.
