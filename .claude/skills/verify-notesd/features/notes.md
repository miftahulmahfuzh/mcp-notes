# Notes

## Sub-features
- Create a note (plain-text body; `#hashtags` become lower-cased tags on every write).
- Replace the body (update) or append to it; every body change keeps the old body as a revision.
- Revert to a revision. Soft delete and restore.
- List newest-edited first, filter by tag.
- Session links (`note_session_links`, see `projects.md`): a soft delete keeps a note's links to
  sessions; purging it from the bin (hard delete) drops its link rows (`on delete cascade`).

## How to get to it (user POV)
Wall: the `New note` button, type into `Note text`, the card's `Delete note`. Claude Code: `/n save ...`
(MCP `create`, `update`, `append`, `delete`, `restore`, `revisions`, `revert`). HTTP: `/api/notes`.

## Driving it with verify.sh
```sh
$V api RUN POST /api/notes '{"body":"first #alpha"}'          # 201, id like X-XXX, tags ["alpha"]
$V api RUN PATCH /api/notes/<id> '{"body":"second #beta"}'     # tags now ["beta"]
$V mcp RUN revisions '{"id":"<id>"}'                          # the old body is listed
$V mcp RUN revert '{"id":"<id>","revision":<n>}'              # body back to "first #alpha"
$V api RUN DELETE /api/notes/<id>; $V api RUN GET /api/notes  # gone from the list
$V sql RUN "select id, deleted_at is not null as deleted from notes"   # soft: row still there
```
Session-link cascade (needs `up --sessions` for a node id):
```sh
$V mcp RUN link_note '{"note_id":"<id>","node_id":"<node>"}'                  # linked:true
$V api RUN DELETE /api/notes/<id>                                              # soft delete
$V sql RUN "select count(*) from note_session_links where note_id='<id>'"      # 1: link kept
$V api RUN DELETE /api/bin/notes/<id>                                          # purge (hard delete)
$V sql RUN "select count(*) from note_session_links where note_id='<id>'"      # 0: cascaded
```
Proof: the read-back after each write, the SQL row for soft delete, and the link-row counts.

## Gotchas
- Ids are generated by the server. Capture them from the create response; never invent one.
- Lookup tolerates case and a missing dash (`ab32`), so test that when touching id parsing.
